2 · 같은 계약을 가진 코드부터 하나로 모았습니다

대상정리 전정리 후
테스트용 Transporthost와 client에 같은 파일 두 개test-support의 한 파일을 함께 사용
provider 실행프로필·저장 읽기·쓰기·삭제마다 await/응답/오류 처리가 반복됨호스트 안의 invokeCapability로 공통 처리
실험 HTTP 응답Android와 iOS 서버가 CORS·외부 페이지·응답 쓰기를 반복함실험 전용 공통 모듈과 플랫폼별 설정으로 분리
 
void invokeCapability(
  id,
  method,
  () => provider.get(config.manifest.id, params.key),
  (value): StorageGetResult => ({ value }),
);

각 기능은 “실제로 실행할 일”과 “외부로 보낼 결과 모양”을 넘깁니다. 공통 함수가 완료를 기다리고 응답하며, 실패하면 고정 오류를 보내고 원래 오류는 호스트에만 보고합니다.

() => provider.get(...)처럼 호출을 감싼 이유도 있습니다. 메서드만 떼어 넘기면 this가 사라져 provider가 자기 상태를 읽지 못할 수 있습니다. 새 테스트는 실제 상태를 가진 provider 인스턴스로 이 문제를 잡습니다.

호스트의 엄격한 알림 입력 검사와 클라이언트의 확장 필드 허용 검사는 이름이 비슷해도 계약이 달라 합치지 않았습니다. 공통화의 기준은 줄 모양보다 입력·오류·순서·책임이 같은지입니다.

3 · 같은 값의 선택지는 switch, 순서 있는 검사는 if

switch (method) {
  case STORAGE_METHODS.SET:
    // write and show success
    break;
  case STORAGE_METHODS.GET:
    // read and validate the returned value
    break;
  case STORAGE_METHODS.DELETE:
    // delete and show success
    break;
}

저장 예제 화면은 같은 method의 세 가지 선택을 나누므로 switch로 바꿨습니다. 삭제 처리가 마지막 else에 숨어 있지 않고 이름으로 드러납니다.

초기화 여부·권한·인자 검사처럼 조건이 다르고 실행 순서가 중요한 코드는 if와 조기 반환을 유지했습니다. 명세에서 정한 오류 우선순위를 보기 쉽게 남기는 것이 중요합니다.

4 · 빠진 테스트를 추가하니 실제 문제가 보였습니다

중단된 T24의 로컬 실험 서버에서 절대경로와 심볼릭 링크가 지정한 앱 폴더 밖으로 연결될 수 있었습니다. 임시 폴더에 테스트 파일을 만들어 HTTP로 요청하니 네 사례에서 404 대신 200이 반환됐습니다.

package_root = (fixtures / group).resolve(strict=True)
source = (package_root / resource).resolve(strict=True)
if not source.is_relative_to(package_root):
    return Response(b"Unknown app or outside package", status=404)

파일의 실제 위치를 먼저 확인해 심볼릭 링크까지 풀고, 선택한 앱 루트 안에 있는지 검사합니다. 절대경로도 입구에서 거절합니다. 같은 앱 내부를 가리키는 정상 링크는 계속 읽을 수 있도록 대조군을 두었습니다.

이 수정은 기존 보안 요구인 SPEC §7·§9.6과 연결됩니다. 실제 사용자 파일 대신 임시 테스트 데이터로 재현했고, 모든 테스트 서버는 비어 있는 로컬 포트를 사용한 뒤 종료됩니다.

추가로 배열의 상속된 toJSON이 실행되지 않는지도 검사했습니다. 호출 횟수가 0이고 원래 JSON 값이 유지되는지 확인하는 방식이라 내부 구현 줄을 그대로 따라가는 테스트와는 다릅니다.

5 · 이제 기본 검사를 한 명령으로 실행합니다

pnpm run check

TypeScript 테스트 → Python 실험 서버 테스트 → 타입 검사 → Biome → 브라우저 예제 두 빌드를 차례로 실행합니다. 하나라도 실패하면 다음 검사로 넘어가지 않습니다.

Biome는 코드 형식과 지원하는 언어의 규칙을 검사합니다. Python 테스트는 표준 라이브러리 unittest로 실행하며 새 패키지를 설치하지 않습니다. 네이티브 앱의 실제 동작 검증은 해당 task가 진행 중일 때 별도로 수행합니다.

T28 · Committing the first response of an iOS Basic challenge

이제 두 OS의 쿠키 보관함이
같은 값을 가집니다.

47번에서 첫 401의 쿠키를 인증 콜백에서 읽을 수 있다는 것을 확인했습니다. 이번에는 그 값을 실제로 커밋하도록 iOS 연구용 브로커를 바꾸고, 양쪽 OS에서 다시 수집했습니다. Android 코드는 바꾸지 않았습니다.

63사례 × 4수집 · 검증 1,790건 · 서버 기록 474행전부 통과iOS 재전송 자체는 유지

1 · 무엇을 바꿨나

규칙은 한 줄입니다. 미니 앱 요청 하나에 쿠키 커밋은 한 번, 첫 응답으로. Android는 요청을 한 번만 보내니 원래 그렇게 동작했고, iOS만 맞추면 됩니다.

// 1. 인증 콜백이 첫 401을 넘겨줍니다
if let http = challenge.failureResponse as? HTTPURLResponse {
    exchanges[task.taskIdentifier]?.challengeResponse?(http)
}

// 2. 두 경로가 같은 커밋 함수를 쓰고, 먼저 온 쪽만 반영됩니다
var committed = false
let commitOnce: (HTTPURLResponse) -> Void = { [unowned self] response in
    if committed { return }
    committed = true
    self.commit(session, generation, include, label, url, response)
}
exchange = client.start(request, headers: commitOnce, challenged: commitOnce, finished: ...)

같은 commit 함수를 쓰므로 credentials:"omit"과 세션 초기화 검사가 그대로 적용됩니다. 새 사례 2개로 이 점도 확인했습니다.

첫 응답에 쿠키가 없으면 어떻게 될까요? 그래도 커밋 기회는 첫 응답이 가져갑니다. 그래서 두 번째 응답에만 있는 쿠키는 무시되고, 두 번째 시도를 보낸 적 없는 Android와 결과가 같아집니다.

이미 받아들인 규칙인 "헤더가 전달될 때 커밋한다"를 다듬었기 때문에 계약서와 ADR 0027에 수정 내용을 적었습니다. iOS의 Basic 401만 인증 콜백 시점에 커밋합니다.

2 · 먼저 본 실패

브로커를 고치기 전에 새 기준으로 iOS를 돌렸더니 예상한 4개 사례만 실패했습니다.

사례고치기 전 iOS 보관함기대값 (Android와 같음)
시도마다 다른 쿠키attempt=2attempt=1
첫 시도에만 쿠키비어 있음first=1
두 번째 시도에만 쿠키second=2비어 있음
쿠키 줄이 두 개c=3a=1, b=2

omit 사례와 초기화 사례는 고치기 전에도 통과했습니다. 이 둘은 결함을 잡기보다, 새 커밋 경로가 기존 보호를 지키는지 확인하는 사례입니다.

3 · 결과

63개 사례가 양쪽 OS에서 각 2회, 모두 통과했습니다. 미니 앱이 받는 결과, 서버 기록, 보관함이 두 OS와 두 수집에서 모두 같았습니다.

이벤트 기록에서도 커밋 횟수를 확인했습니다. 서버 도착은 2번인데 커밋은 1번입니다.

c06-basic-401-first-attempt-only (iOS)
  headers  challenged   ← 인증 콜백의 첫 401
  commit   challenged   ← first=1 저장. 두 번째 응답은 무시
  headers  me           ← 다음 요청의 응답

실패 횟수를 세는 서버에는 iOS가 두 번으로 보입니다. 재전송을 막는 유일한 방식은 올바른 401을 잃기 때문에 이미 제외했고, 그래서 계약서에 적었습니다. 본문 차이는 서버가 401 본문을 시도마다 바꿀 때만 보입니다.

이번 시험의 한계

  • SDK 헤더가 약속하지 않는 동작에 기대고 있습니다. 측정은 iOS 26.4.1, Basic, HTTP/1.1뿐이라 지원하는 OS 버전마다 다시 측정해야 합니다.
  • 연구용 브로커에만 적용했습니다. 제품 코드, SPEC, 프로토콜은 바뀌지 않았습니다.
  • C04와 C09–C12, 실제 Portal, 브리지는 여전히 시험하지 않았습니다.
현재 상태: 완료 수는 6 / 44 그대로이고, 이번 변경은 아직 커밋하지 않았습니다. 시험용 키는 휴지통에 있어 직접 비워 주셔야 합니다.

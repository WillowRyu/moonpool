T22 · Native targets and toolchain

실험을 시작하기 전,
준비된 도구부터 확인했습니다.

Android·iOS 개발 도구가 이 Mac에 이미 설치되어 있습니다. 첫 실험 후보와 아직 확인하지 않은 항목을 기록하고, T23·T24에서 무엇을 관찰할지 먼저 정했습니다.

1 · 준비된 환경과 남은 확인

항목현재 확인한 것다음에 확인할 것
공통Apple silicon Mac · Node 22.19.0 · pnpm 11.1.3선택한 문맥에서 TypeScript 호스트 커널 실행
AndroidAndroid Studio 2025.3 · JDK 17/21 · Emulator 36.6.11실험 프로젝트의 JDK·Gradle·AGP 조합과 빌드
Android 가상 기기Pixel 7 Pro 프로필 1개 · API 37 ARM64 · 16KB 페이지 구성실제 부팅·OS·WebView 버전·기능 지원
iOSXcode 26.4.1 · SDK 26.4 · 사용 가능한 시뮬레이터 런타임실험 앱의 빌드·설치·실행
iOS 가상 기기iPhone 6개·iPad 5개 설정 · 모두 종료 상태첫 후보 iPhone 17 Pro에서 WKWebView 동작
실기기두 플랫폼의 기기 목록에 현재 표시된 기기 0개보유 여부·연결·테스트할 기기는 추후 확인

iOS 런타임의 표시 이름은 26.4이고 상세 버전은 26.4.1입니다. SDK와 런타임의 상세 버전은 각각 기록했습니다. 지금 설치된 버전이 제품의 최소 지원 버전으로 정해진 것은 아닙니다.

Android에서 발견한 조건
설치된 OS 이미지는 API 37의 16KB 구성뿐입니다. 별도 Google Play 이미지에는 Pre-Release 표시도 있어 전체를 일반적인 지원 환경으로 취급하지 않습니다. SDK 목록 조회는 성공했지만 정수 검사·XML 버전 경고가 나왔습니다. 원인은 아직 진단하지 않았고, 로컬 메타데이터와 가상 기기 설정으로 후보 정보를 교차 확인했습니다.

도구별 버전·확인 근거·남은 조건 · 영문에 상세 기록을 남겼습니다. 이번 task에서는 SDK를 설치하거나 가상 기기를 부팅하지 않았습니다.

2 · 설치된 SDK와 실행 가능한 기기는 다릅니다

이름쉬운 뜻이번에 확인한 범위
SDK앱을 만들 때 쓰는 도구와 API 묶음어떤 버전이 설치되어 있는지
Android 시스템 이미지 / iOS 런타임가상 기기가 실행할 운영체제 묶음어떤 OS 묶음이 있는지
AVD / 시뮬레이터 기기 설정화면·기종·OS를 조합한 가상 휴대폰 설정만들어 둔 설정과 현재 실행 상태
WebView / WKWebView앱 안에서 웹 콘텐츠를 실행하는 화면실제 앱에서의 로딩·출처·저장 동작은 다음 실험

예를 들어 Android API 34의 SDK가 있다고 해서 API 34 가상 기기도 있는 것은 아닙니다. 또 Android OS 버전만 보고 필요한 WebView 메시지 기능이 지원된다고 판단할 수 없어, T25에서 실행 중인 엔진과 기능 지원을 확인합니다.

3 · 이번에는 환경 확인 명령을 읽어봅니다

emulator -list-avds
emulator -accel-check
adb devices -l

첫 줄은 만들어 둔 Android 가상 기기를 보여줍니다. 둘째 줄은 가상 기기를 빠르게 실행하는 하드웨어 가속 조건을 확인합니다. 셋째 줄은 지금 연결된 기기나 실행 중인 에뮬레이터를 보여줍니다.

이 Mac에서는 가상 기기 설정 1개와 가속 가능 상태를 확인했고, 연결 목록은 비어 있었습니다. 이 결과만으로 실험 앱이 실행됐다고 말할 수는 없습니다.

xcodebuild -version
xcodebuild -showsdks
xcrun simctl list runtimes --json
xcrun simctl list devices available --json

위에서부터 Xcode 버전, 설치된 SDK, 시뮬레이터 OS 묶음, 사용 가능한 기기 설정을 확인합니다. --json은 결과를 프로그램이 읽기 쉬운 구조로 받는 옵션입니다. 기기의 개인 이름·고유 번호는 저장소 기록에서 제외했습니다.

판단을 나누는 이유
도구가 있다 → 빌드가 된다 → 기기가 부팅된다 → 웹 앱이 열린다 → 출처·권한 검사가 맞게 동작한다
각 단계는 실제 결과를 따로 확인해야 합니다.

4 · 코드를 쓰기 전에 관찰할 조건을 정했습니다

T23·T24에서는 고정된 앱 A와 B, 공개 테스트 문자열을 사용합니다. 아래는 아직 실행하지 않은 실험 기준이며, 두 OS에서 각각 결과를 기록합니다.

실험확인할 질문
P01 · 빌드·부팅정확히 어떤 도구·OS 조합으로 앱이 실행됐는가?
P02 · 앱별 출처A와 B가 서로 다른 안정된 출처를 가지는가?
P03 · 로컬 파일HTML·JS·CSS와 JSON 파일이 올바르게 로드되는가?
P04 · 저장 분리B가 A의 저장 값을 읽지 못하는가? 저장 기능 자체가 없는 경우도 구분했는가?
P05 · 저장 수명새로고침·화면 재생성·앱 프로세스 재실행 때 값이 어떻게 되는가?
P06 · 다른 앱 접근정상 접근은 되면서 다른 앱의 DOM·저장소 접근은 막히는가?
P07 · 페이지 이동내부 이동·새로고침·다른 출처 이동과 복귀를 어떻게 관찰하는가?
P08 · 경로·네트워크패키지 밖 파일을 읽거나 없는 파일을 네트워크에서 찾으려 하지 않는가?
P09 · 요청 출처브라우저 출처·CORS 동작과 네이티브에서 확인할 신원 정보가 무엇인가?
P10 · 재현같은 조건으로 다시 실행해 정상·실패 결과를 비교할 수 있는가?

이 항목들은 보안 명세 §8·§9와 연결됩니다. 현재 moonpool://<mini-app-id>/ 규칙은 유지하고, 플랫폼에서 충족하지 못하는 부분은 결과로 기록해 T28의 구체적인 결정안에 연결합니다. Android의 공식 HTTP(S) 로더를 비교용으로 사용해도 그것이 운영 출처 변경 승인을 뜻하지 않습니다.

5 · 다음은 T23, 그리고 같은 조건의 T24입니다

T23에서는 기존 Android 가상 기기를 사용해 작은 실험 앱의 빌드·실행과 실제 로딩 동작을 확인합니다. 빌드 도구 조합은 시작할 때 맞춰 고정합니다. T24는 같은 실험을 iOS 시뮬레이터에서 수행합니다.

호스트 앱 기술과 TypeScript 커널의 실행 위치는 T27에서 두 플랫폼의 근거를 보고 선택합니다. 제품 최소 OS와 실기기 지원 범위도 현재 설치 목록만으로 확정하지 않습니다.
